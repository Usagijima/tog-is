# 实验记录使用说明

## 三条铁律

1. **先记录，再动手。** 每次跑实验/改代码之前，先在下面新建一条记录，填好"今天打算做什么"。跑完再补结果。
2. **只记录事实，不修饰结果。** 失败就写失败，数字难看就写难看的数字。这些记录以后就是论文的"数据卡"和附录素材。
3. **每条记录必须能复现。** 任何人（包括三个月后的你自己）拿着这条记录，能找到对应的代码版本、数据和参数，重跑出相同结果。

## 每条记录填这些（照抄上面的模板）

| 字段 | 怎么填 | 为什么 |
|---|---|---|
| 日期 | 2026-10-04 | 时间线是排查问题的第一条线索 |
| 编号 | EXP-001 | 论文里引用结果时用编号，例如"见 EXP-003" |
| 阶段 | 对应方案第 21 节的 M1-M8 | 知道自己进行到哪 |
| 目的 | 一句话说清要验证什么 | 防止跑了一半忘了初衷 |
| 脚本/版本 | 文件名 + 改了什么 | 定位代码 |
| 数据快照 | data 文件的 SHA256（在 source_manifest.json 里） | 证明用的是哪份数据 |
| 参数 | 所有能调的数都要写：随机种子、阈值、路径 | 差一个参数结果可能就不同 |
| 预期 | 动手前写下你猜会发生什么 | 防止事后编理由 |
| 实际结果 | 客观数字 + 输出文件路径 | 论文的素材 |
| 与预期差异 | 一致/不一致，哪里不一致 | 不一致处往往就是发现 |
| 下一步 | 基于结果决定做什么 | 保持连续 |
| 坑与备忘 | 环境报错、下载失败等 | 同类问题不用重踩 |

## 什么情况要新建一条记录

- 每次运行任何脚本（哪怕是重跑）
- 每次修改脚本后
- 每次环境变动（装库、换 Python 版本）
- 每次"我想试试某个想法"——不管试成没成

## 什么情况不用记

- 纯阅读、查资料、问 AI 问题（这些记在你自己的学习笔记里就行）
